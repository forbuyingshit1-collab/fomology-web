## บทนี้คุณจะได้อะไร

คุณจะเลือก `t2v`, `i2v`, `v2v` หรือ `draft_enhance` จากสื่อต้นทาง และแยก “ต่อคลิป” ออกจาก “แก้คลิป” ได้

## เข้าใจใน 1 นาที

| ถ้าคุณมี | Mode | งานของ Mode |
| --- | --- | --- |
| ไอเดียหรือข้อความ | `t2v` | สร้างภาพและการเคลื่อนไหวจาก Prompt |
| ภาพนิ่ง 1–10 ภาพ | `i2v` | ใช้ภาพเป็น Frame/Keyframe แล้วกำกับการเคลื่อน |
| MP4 ที่ต้องการให้เรื่องดำเนินต่อ | `v2v` | ต่อจากเฟรมท้ายและตรรกะของคลิปเดิม |
| Draft Cache จาก FLUX.3 | `draft_enhance` | รักษา Generation เดิมและเลือกความละเอียดส่งมอบ |

ถ้าต้องลบคน เปลี่ยนวัตถุ หรือแก้เหตุการณ์ **ภายในคลิปเดิม** ให้ใช้ FLUX Video Edit ซึ่งเป็น Endpoint และ Schema แยก ไม่ใช่ `v2v`

Guided Project ไม่มีรูปหรือวิดีโอต้นทาง จึงใช้ `t2v`

## ทำตามทีละขั้น

1. ถามก่อนว่า “ฉันมีสื่อต้นทางจริงหรือมีแค่ไอเดีย?”
2. ถ้าเป็นข้อความอย่างเดียว เลือก `t2v` และห้ามใส่ `keyframes` หรือ `start_video`
3. ถ้ามีภาพ เลือก `i2v` และตรวจว่า Prompt บอกสิ่งที่ต้องเคลื่อน ไม่บรรยายภาพซ้ำทั้งหมด
4. ถ้ามีวิดีโอ เลือก `v2v` เฉพาะเมื่อต้อง **ต่อหลังเฟรมสุดท้าย**
5. ถ้ามี `.bin` Draft Cache เลือก `draft_enhance` โดยไม่เขียน Prompt ใหม่

## ตัวอย่างไม่ดี / ดีขึ้นอย่างไร

**ไม่ดี:** มี MP4 แล้วสั่ง “ลบคนด้านหลังโดยไม่เพิ่มเวลา” ด้วย `v2v` — Mode นี้จะต่อคลิป ไม่ได้แก้เฟรมเดิม

**ดีขึ้น:** ส่งงานไป FLUX Video Edit และใช้ `v2v` เฉพาะคำสั่งอย่าง “ให้เจ้าของร้านเดินต่อจากประตูไปหลังเคาน์เตอร์โดยไม่ตัด”

## ลองทำ

เลือก Mode ให้ทั้งสี่โจทย์: (1) ไอเดียร้านกาแฟ, (2) ภาพสินค้าหนึ่งภาพ, (3) คลิปที่ต้องต่ออีก 6 วินาที, (4) Draft Cache ที่ชอบแล้ว คำตอบควรเป็น `t2v`, `i2v`, `v2v`, `draft_enhance` ตามลำดับ

## เช็กก่อนผ่าน

- โปรเจกต์ร้านกาแฟเลือก `t2v`
- ไม่ใส่ Field ของ Mode อื่นใน Payload
- เข้าใจว่า Continuation ไม่ใช่ Editing
- รู้ว่า Draft Enhance ใช้ Cache ไม่ใช่การ Submit Prompt เดิมใหม่
